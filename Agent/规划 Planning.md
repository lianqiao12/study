# 规划 Planning（任务分解与自我反思）

> 标签：#概念/Agent #规划 #Planning #ReAct #Reflexion #ToT

## 1. 为什么需要规划

复杂任务无法一步到位。Agent 必须把「大目标」拆成「可执行的小步骤」，并在执行中动态调整。规划分两个子方向（Lil'Log 综述）：**任务分解** 与 **自我反思**。

## 2. 任务分解（Task Decomposition）

| 方法 | 思路 | 适用 |
|------|------|------|
| **CoT（Chain of Thought）** | 提示模型「一步步思考」，把任务显式拆成推理链 | 通用、简单任务 |
| **ToT（Tree of Thoughts）** | 每步探索多种可能，形成树状搜索（BFS/DFS），可回溯 | 需要搜索/试错的博弈、规划 |
| **LLM+P** | 借助外部经典规划器（PDDL 语言）做长程规划 | 强约束、可形式化的问题 |
| **子目标分解** | 让 LLM 自发生成中间里程碑 | 多步工具调用任务 |

> ToT 本质是给 LLM 加了一个「搜索空间」，代价是多次推理调用。

## 3. 自我反思（Self-Reflection）

让 Agent 在行动后「复盘」，把错误转化为下一步的输入。

### 3.1 ReAct（Yao et al., 2023）
把**推理**与**行动**耦合进同一个循环：

```text
Thought:  我需要先查一下 X 的定义
Action:   search(X)
Observation: X 的定义是 ...
Thought:  那我应该 ...
Action:   ...
```

- 动作空间 = 任务特定离散动作 + 语言空间（自然语言推理）
- 在知识问答和决策任务上，显著优于「只行动（Act-only）」基线
- 是当今大多数 Agent 的「标准循环骨架」

### 3.2 Reflexion（Shinn & Labash, 2023）
带动态记忆与自我反思的强化学习框架：

- 用启发式函数检测「低效规划」或「幻觉（连续重复同一动作）」，决定是否重置环境
- 把失败轨迹 + 理想反思「样本」喂给 LLM 生成反思，存入**工作记忆**以优化后续计划
- 相比纯 ReAct，多了「把反思沉淀为长期经验」的闭环

### 3.3 其他方法
- **Chain of Hindsight (CoH)**：利用历史反馈序列提升输出
- **Algorithm Distillation (AD)**：把多步轨迹「蒸馏」进模型权重

## 4. 与架构模式的关系

规划循环在 [[智能体架构模式（Workflow与Agent）]] 的「自主 Agent」中处于核心地位；而 [[反思与自我修正 Reflection]] 进一步把它系统化。

## 5. 常见坑

- **长程规划脆弱**：一旦出错难回退，鲁棒性弱于人类试错
- **过度规划**：简单任务硬拆多步反而更慢更贵
