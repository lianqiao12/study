# 主流 Agent 框架对比

> 标签：#概念/Agent #框架 #LangChain #AutoGPT #MetaGPT #CrewAI #OpenAI #Claude

## 1. 框架总览

| 框架 | 定位 | 特点 | 适合 |
|------|------|------|------|
| **LangChain / LangGraph** | 最通用的 Agent/链编排库 | 组件极多、生态大；LangGraph 用图描述状态机 | 需要灵活编排的复杂应用 |
| **AutoGPT** | 早期「自主 Agent」代表 | 给定目标后自我循环规划执行；概念验证性强 | 学习/实验自主 Agent 思路 |
| **BabyAGI** | 极简任务驱动 Agent | 用任务列表 + 优先级循环驱动 | 理解 Agent 最小闭环 |
| **MetaGPT** | 多智能体「软件公司」 | 把 SOP 编码进多角色协作（产品经理/工程师/QA） | 自动化软件开发 |
| **CrewAI** | 角色化多智能体 | 强调「角色 + 任务 + 协作流程」 | 业务流程型多 Agent |
| **Claude Agent SDK（Anthropic）** | 官方 Agent 构建工具 | 与 Claude 模型深度集成，强调工具与子 Agent | 基于 Claude 的生产级 Agent |
| **OpenAI Agents SDK** | 官方轻量 Agent 框架 | Agents + Handoff（交接）+ Guardrails（护栏）+ Tracing | 基于 OpenAI 模型的多 Agent |

## 2. 框架 vs 裸写 LLM API

Anthropic 的警示（重要）：

> 框架便于起步，但容易增加抽象层，**掩盖底层 prompt**，导致难以调试。
> 建议开发者先用 LLM API 直接写几行代码实现模式；用框架时必须**理解底层代码**。

即：框架是加速器，不是黑箱。不懂底层提示工程，框架反而会坑你。

## 3. 选型建议

- **想快速验证想法**：直接调 LLM API + 手写 ReAct 循环（见 [[规划 Planning]]）
- **生产级、单模型生态**：对应厂商 SDK（Claude Agent SDK / OpenAI Agents SDK）
- **复杂编排、多模型**：LangGraph
- **多智能体模拟/软件生成**：MetaGPT / CrewAI

## 4. 共同观察

无论哪个框架，底层都绕不开：
- [[增强型LLM（检索-工具-记忆）]] 的底座
- [[智能体架构模式（Workflow与Agent）]] 的编排思想
- [[构建最佳实践]] 的接口与护栏设计

框架只是把这些模式「打包」了而已。
