# 反思与自我修正 Reflection

> 标签：#概念/Agent #反思 #Reflection #Reflexion #自我修正

## 1. 什么是反思

Agent 不应「一条道走到黑」。反思（Reflection）指 Agent 在行动后**评估自己做得对不对**，把经验沉淀下来指导后续步骤。

它是 [[规划 Planning]] 中「自我反思」子方向的系统化工程实现，也是让 Agent 从「一次得过且过」进化到「越做越好」的关键。

## 2. Reflexion 框架（Shinn & Labash, 2023）

带**动态记忆 + 自我反思**的闭环：

1. Agent 执行轨迹（含失败）
2. 启发式函数 `h_t` 检测问题：低效规划、幻觉（连续重复同一动作）、任务未达成
3. 把「失败轨迹 + 理想反思样本」喂给 LLM，生成自然语言反思
4. 反思存入**工作记忆（长期经验）**，下次规划时读取，避免重蹈覆辙

> 本质：用语言反思替代梯度更新，让 LLM 在不微调权重的前提下「从错误中学习」。

## 3. 评估者-优化者模式（Evaluator-Optimizer）

Anthropic 列出的 Workflow 模式之一，也可用于 Agent 的自我修正：

```text
生成者 LLM ──响应──▶ 评估者 LLM ──反馈──▶ 生成者 LLM ──更优响应──▶ ...
```

- 一个 LLM 产出，另一个在循环中评估并给改进建议
- 适用：有明确评估标准、且迭代有显著价值的任务（如翻译润色、代码评审）

## 4. 与 ReAct 的关系

- **ReAct**：Thought → Action → Observation 的基础循环（见 [[规划 Planning]]）
- **Reflexion**：在 ReAct 之上叠加「反思记忆」，形成「执行-复盘-再执行」的元循环
- 二者常组合使用：日常靠 ReAct 推进，卡住时靠反思跳出局部

## 5. 常见坑

- 反思本身也可能「反思错」（错误归因）→ 需要好的评估信号
- 无限反思循环会烧 token → 设最大迭代次数与早停条件
