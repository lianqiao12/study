# AI Agent 智能体 概述

> 标签：#概念/Agent #智能体 #LLM #agentic-systems

## 1. 什么是 AI Agent

**AI Agent（人工智能体 / 智能体）**：以大语言模型（LLM）为「大脑」，能够**自主感知环境、进行规划、调用工具、采取行动**以完成目标的系统。

更准确地说，业界常把所有相关应用统称为 **agentic systems（代理系统）**。一个典型的 LLM 驱动 Agent 由三部分组成（Lil'Log 综述）：

- **规划 Planning**：把复杂任务拆解为可执行的子步骤
- **记忆 Memory**：保存并利用历史信息（短期上下文 + 长期外部存储）
- **工具使用 Tool Use**：调用外部 API、代码执行、检索等扩展能力

> 一句话记忆法：**Agent = LLM（大脑） + 规划 + 记忆 + 工具**

## 2. Agent 与 Workflow 的区别（Anthropic 视角）

这是理解 Agent 最关键的一组概念：

| 类型 | 定义 | 特点 | 适用 |
|------|------|------|------|
| **Workflow（工作流）** | 通过**预定义代码路径**编排 LLM 和工具 | 可预测、一致、可控 | 定义明确的任务 |
| **Agent（智能体）** | LLM **动态指导**自身流程和工具使用 | 灵活、模型驱动决策 | 无法硬编码路径的开放任务 |

> 核心建议：**优先用最简单方案**。代理系统通常以「延迟 + 成本」换取「性能」，不要一上来就堆复杂 Agent。

## 3. 为什么 Agent 会兴起

1. **LLM 能力跃升**：推理、指令遵循、代码生成能力大幅增强
2. **工具调用（Function Calling）成熟**：模型能稳定地决定「调哪个工具、传什么参」
3. **检索与记忆基础设施完善**：向量库（RAG）、长期存储让 Agent 突破上下文窗口
4. **从「问答」到「办事」的需求转变**：用户要的不是一句话答案，而是跑通一个任务

## 4. 能力边界与适用场景

**适合 Agent**：
- 开放式、路径不可预先写死的问题（如自动修 bug、自动调研）
- 需要模型在循环中根据环境反馈决策
- 环境足够可信（误操作代价可控）

**不适合 / 慎用**：
- 固定流程、明确步骤的任务 → 用简单 Workflow 更稳
- 对一致性、可审计性要求极高的场景 → 需要人工 checkpoint
