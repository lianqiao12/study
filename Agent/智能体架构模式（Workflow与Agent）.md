# 智能体架构模式（Workflow 与 Agent）

> 标签：#概念/Agent #架构模式 #Workflow #编排 #Orchestration

## 1. 总览（Anthropic《Building Effective Agents》）

构建 agentic systems 时，从简单到复杂有一组可复用的**编排模式**。优先用简单模式，按需叠加复杂度。

## 2. Workflow 五大基础模式

### 2.1 提示链 Prompt chaining
把任务拆成**顺序步骤**，每个 LLM 调用处理上一步输出，可在中间插入程序化检查（gate）防跑偏。
- 例：先写大纲 → 再写正文 → 再校对
- 适用：能干净拆解的固定子任务

### 2.2 路由 Routing
把输入**分类**并导向专门的后续任务 / 提示 / 工具。
- 例：客服按意图分流；按难度分派不同档位的模型
- 适用：类别分明、分类准确的复杂任务

### 2.3 并行化 Parallelization
LLM **同时**处理任务，再程序化聚合：
- **分段 Sectioning**：独立子任务并行（如一个模型答询、另一个做安全筛查）
- **投票 Voting**：同任务多次运行取多样输出（如多提示评审漏洞）

### 2.4 编排者-工作者 Orchestrator-workers
中央 LLM **动态**分解任务、委托 worker 并综合结果。与并行化拓扑相似，但子任务由编排者按输入**实时决定**。
- 例：一次改动多个文件的编码任务

### 2.5 评估者-优化者 Evaluator-optimizer
生成者产出，评估者循环反馈（见 [[反思与自我修正 Reflection]]）。
- 例：文学翻译润色、代码迭代

## 3. 自主 Agent（Autonomous Agent）

- 从用户命令/交互开始 → 规划并独立操作 → 基于**环境反馈**（工具结果、代码执行等「真值」）评估进度 → 在检查点/阻塞处可暂停等人反馈
- 本质：LLM 在循环中基于环境反馈调用工具，实现往往直接，关键在**工具集设计**
- 适用：开放性问题、路径无法硬编码、且信任模型决策（如 SWE-bench 编码 Agent、计算机操作 Agent）

## 4. 选型决策

```text
任务步骤固定、可预测？ ──是──▶ Workflow（选上面合适的模式）
        │否
        ▼
需要模型动态决策、开放路径？ ──是──▶ 自主 Agent
```

> 经验法则：**能 workflow 解决的，别上 agent**。Agent 用延迟和成本换灵活性。
