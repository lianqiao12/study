# 多智能体协作 Multi-Agent

> 标签：#概念/Agent #多智能体 #Multi-Agent #协作 #Orchestrator

## 1. 为什么要多智能体

单个 Agent 同时当「规划者 + 执行者 + 评审者」容易顾此失彼。多智能体通过**角色分工**把职责拆开，提升专业性与可控性。

## 2. 主要协作形态

### 2.1 编排者-工作者（Orchestrator-Workers）
- 一个「主编排 Agent」负责拆解任务、派活、汇总
- 多个「工作者 Agent」各司其职（如一个写代码、一个写测试）
- 对应 [[智能体架构模式（Workflow与Agent）#2.4 编排者-工作者 Orchestrator-workers]]

### 2.2 辩论 / 对抗（Debate / Adversarial）
- 多个 Agent 就同一问题给出方案并互相质疑
- 通过「红队」暴露漏洞，提升鲁棒性
- 例：一个提方案，另一个专门找茬

### 2.3 角色扮演沙盒
- 给每个 Agent 设定人设、记忆、目标，模拟社会协作
- 经典案例 **Generative Agents**（25 个虚拟角色小镇，具备日常行为规划与记忆）

## 3. 通信机制

- **共享黑板（Blackboard）**：所有 Agent 读写同一状态空间
- **消息传递**：Agent 间显式发消息（类似本对话的 team 模式）
- **交接 Handoff**：一个 Agent 把任务「转交」给更合适的 Agent（OpenAI Agents SDK 的核心概念）

## 4. 收益与代价

| 收益 | 代价 |
|------|------|
| 职责清晰、专业度高 | 通信开销大、token 消耗高 |
| 可并行、可隔离失败 | 协调复杂、易陷入死循环 |
| 便于权限/沙箱隔离 | 调试困难（链路长） |

## 5. 实践建议

- 先确认「单 Agent + 好工具」是否够用；不够再拆
- 明确每个 Agent 的边界与交接协议（Handoff），避免职责重叠
- 设全局监督者（Supervisor）防止 Agent 互相「甩锅」或无限协商
