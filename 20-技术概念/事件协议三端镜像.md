# 事件协议三端镜像

#概念/通信

> ai-resume 的核心约定:**同一份 SSE 事件 schema 在 web / Go / Python 三端各自镜像一份**,并做版本管理。这是 seam ④。

## 事件结构
```json
{
  "schema_version": "1",
  "type": "text",
  "run_id": "uuid",
  "agent_id": "ats-optimizer",
  "data": {}
}
```

## 事件类型
`status` / `plan` / `text`(增量文本) / `tool_call` / `tool_result` / `section_patch` / `done` / `error`

## 为什么这样设计
- 三端独立技术栈(React / Go / Python),但事件格式强制一致 → 任一层改了协议,另两层必须同步,否则流解析失败。
- 版本化:`schema_version` 是字符串,破坏性变更升主版本,增量变更升次版本且向后兼容。
- Go 端把**整个事件数组**持久化到 `agent_runs.events`,用于客户端逐字重放一次运行。

## 落点
- `apps/api/internal/model/event.go`
- `apps/agent/app/schemas/event.py`
- `apps/web/lib/event.ts`
