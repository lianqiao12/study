# 连接池 Connection Pool

#概念/数据库 #概念/Go

> 连接池 = 预先建好一批可复用的数据库连接,请求来时"借"一个、用完"还"回去,而非每次现建现断。

## 为什么需要
- 直接连库:每次 `建连 → 执行 → 关闭`,建连要三次握手 + 鉴权,开销大、慢。
- 高并发下反复建连会把数据库**连接数打爆**。
- 连接池:启动时预建 N 个连接放"池"里,请求借取、用完归还、他人复用。

## 生活类比
共享单车桩:不用每人买一辆车(每次新建连接),大家共用一排车(池);骑完停回桩(归还),下一个人接着骑。车数有限(池大小),高峰可能要等。

```
请求A ──借──▶ [池: 连接1 连接2 连接3] ──还──▶ 请求B
请求C ──借──▶                          ──还──▶ 请求D
```

## 在 Go 里(pgx)
```go
pool, _ := pgxpool.New(ctx, databaseURL)  // 启动时建全局池
// repository 从池取连接,不自己 sql.Open
conn, _ := pool.Acquire()
defer conn.Release()   // 必须还!否则连接泄漏、池耗尽
```
- `pgxpool.Pool` 内含多个到 Postgres 的真实连接。
- 池自动扩容(到上限)、回收空闲连接、断线重连。

## 易错点
- **借了必须还**:忘了 `Release()` → 连接不回池 → 慢慢耗尽 → 后续请求卡死。
- 池太小:并发上不去;池太大:压垮数据库。需按负载调 `max_conns`。
- 池中连接可能"过期",好池实现会在借出时校验/重连。
