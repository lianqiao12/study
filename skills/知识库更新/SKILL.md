# 知识库更新

将零散知识点沉淀为 Obsidian 笔记,存到用户的知识库根目录
`C:\develop\obsidian\doc\zzz`(在 WSL 下为 `/mnt/c/develop/obsidian/doc/zzz`)。

知识库采用结构化分类,用 `[[双链]]` + `#标签` 组织。本技能保证写入的笔记
自动落位到正确分类目录,并同步更新首页索引,使新笔记可被图谱/搜索立刻发现。

## 何时使用

- 用户主动要求"记到知识库 / 更新笔记 / 存进 obsidian / 沉淀知识点"。
- 对话中出现了值得长期保留的内容(架构总结、技术概念、踩坑修复、学习路线),
  且用户暗示要保存。
- 不要对每一次闲聊都触发;只在用户明确要求或内容明显属于"知识资产"时启用。

## 知识库结构

```
zzz/
├── 00-索引/首页.md            # 索引地图,用 [[双链]] 串联所有笔记
├── 10-项目笔记/               # 具体项目的解读与架构
├── 20-技术概念/               # 通用技术原理(SSE、Docker 路径等)
├── 30-踩坑记录/               # 问题现象→根因→修复的复盘
└── 40-学习路线/               # 作为学习项目,从哪接手、怎么写
```

分类前缀数字用于排序;新增笔记放进对应目录即可。分类约定见
`references/categories.md`。

## 执行流程

1. **确认范围**。若用户未说明写什么,先用一问确认:要写哪些知识点
   (项目架构 / 技术概念 / 踩坑记录 / 学习路线)。
2. **落盘笔记**。为每条知识点生成一份 `.md`,文件名用中文短句(如
   `docker-compose 路径错位导致 make up 失败.md`),放在对应分类目录。
   笔记内使用 `[[双链]]` 指向相关笔记,并打 `#标签`(参见 `references/categories.md`)。
3. **更新首页索引**。调用 `scripts/update_kb.py` 重新扫描目录、重建
   `00-索引/首页.md` 的索引区块,确保新笔记被收录:
   ```bash
   python3 scripts/update_kb.py --root /mnt/c/develop/obsidian/doc/zzz
   ```
4. **回执**。告诉用户写了哪些文件、放在哪个分类,并提醒可在 Obsidian 打开首页查看。

## 笔记写作约定

- 首行 `# 标题`,紧跟 `#标签` 行(如 `#概念/容器`)。
- 用 `[[笔记名]]` 做双向链接,而非普通超链接。
- 踩坑类笔记固定含:现象 / 根因 / 修复 / 教训 四段。
- 不写废话;聚焦可复用、可检索的信息。

## 资源

- `scripts/update_kb.py` — 扫描分类目录、重建首页索引的确定性脚本。
- `references/categories.md` — 分类目录与标签约定。
