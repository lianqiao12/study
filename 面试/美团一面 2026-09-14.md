## 一、直播间项目与埋点

### Q1. 项目几个人开发、多少 PD、多大体量？只有一个后端吗？
**【答法】** 先报全局再聚焦自己：团队 〔后端 N / 前端 N / PD N〕 人，直播间日均 DAU 〔N〕、峰值 QPS 〔N〕、日均埋点 〔N〕 条；我负责 〔埋点采集链路 / 服务端落库 / 查询接口〕 模块，〔是/否〕唯一后端。
**【深入】**
- 体量要能换算：DAU × 人均事件数 ≈ 日均上报量；大促峰值通常是日常的 3–10 倍，要提前压测。
- 若只有一个后端，强调**端到端 owner 意识**：从 SDK 协议、采集服务、存储到看板全链路你都碰过。
**【面试官意图】** 确认你是不是「只写自己那一亩三分地」，有没有项目全局视野和量级概念。
**【追问预演】** 「峰值 QPS 你是怎么扛的？」「埋点服务和业务服务混部吗？」→ 准备：独立采集服务 + Kafka 削峰 + 限流降级。

### Q2. 埋点上报最终数据存到哪？埋点平台底层怎么存储？会丢吗？
**【答法】** 链路：客户端 SDK → 网关/采集服务 → **Kafka** → Flink 实时计算 → 落库；存储分层：实时 OLAP 用 **ClickHouse/Doris/ES/Druid**，离线数仓用 **Hive/HDFS**。
**【深入】**
- **为什么用 Kafka 做缓冲**：解耦采集与计算，削峰填谷；按 `user_id`/`room_id` 分区保证同主体有序。
- **OLAP 选型逻辑**：ClickHouse 列存 + 向量化，适合海量事件聚合；Druid 适合时序切片；ES 适合即席检索。
- **会丢吗——分三层看**：
  1. 采集端→Kafka：生产者 `acks=all` + 重试；若客户端断网且无本地缓冲 → **可能丢少量**（弱网场景）；
  2. Kafka 内部：多副本（replication factor≥3）+ ISR 机制，broker 宕机不丢；
  3. Kafka→落库：Flink **checkpoint + 两阶段提交（exactly-once）**，下游重复写靠**幂等主键**兜底。
- 结论：**链路内不丢，极端弱网/客户端崩溃可能丢少量，靠本地落盘+重试+采样降级兜底**。
**【面试官意图】** 看你知不知道「数据管道」的每一环，以及有没有数据可靠性意识。
**【追问预演】** 「Kafka 怎么保证不丢？」「exactly-once 怎么实现？」「ClickHouse 表怎么设计（稀疏索引/物化视图）？」

### Q3. 上报这个数据合理吗？采集的都是什么数据？为什么这种数据要存到服务端？
**【答法】** 合理，行为埋点是行业标配，衡量「曝光→点击→停留→转化」漏斗；采集进入/离开、商品点击、下单、停留、设备/网络等；存服务端因为客户端不可信、需统一清洗、支撑 BI/推荐。
**【深入】**
- **为什么不能只放客户端**：① 本地数据可篡改（刷量）；② 易丢失（卸载/清缓存）；③ 无法跨端关联用户画像。
- **服务端价值**：去重、补全维度、关联订单、构建实时大屏与推荐特征。
- **隐私合规**（加分项）：敏感字段脱敏、 GDPR/个保法合规、用户可关闭采集。
**【面试官意图】** 看你做事有没有「为什么」的思考，而不是「需求让我做我就做」。
**【追问预演】** 「埋点数据怎么防刷？」「埋点 SDK 体积和性能怎么权衡？」

### Q4. 有没有开发时才发现不该由你们来开发的例子？没有技术方案吗？
**【答法】** 诚实举例：〔如「直播间实时榜单」开发中发现属于算法/数据平台职责，或依赖未就绪能力〕；根因是**需求/SDA 评审没拉通边界**；改进是「进来先写一页技术方案，明确职责边界+依赖方+接口契约」。
**【深入】** 区分两类：
- 职责错配：本该别的团队做；
- 依赖未就绪：别人接口没好你先写了，后期返工。
- 两者都靠**技术方案文档 + 评审会**提前暴露。
**【面试官意图】** 看你有没有「技术决策能力」和「踩坑后的方法论沉淀」，而不是闷头写。
**【追问预演】** 「那你后来怎么避免？」「技术方案模板长啥样？」

### Q5. 上线之后有没有问题？线上 bug 之类？
**【答法】** 准备一个真实案例，按「现象→定位→根因→修复→复盘」讲；若没有大 bug，也要有一个「小问题快速定位恢复」的例子。
**【深入·示例】** 大促埋点量翻倍 → Kafka 消费 lag 暴涨 → ClickHouse 写入延迟 → 看板数据滞后；定位为单分区热点；修复：扩分区 + 调批写大小 + 加容量预警 + 压测基线。
**【面试官意图】** 线上素养 = 监控意识 + 排查思路 + 复盘闭环。
**【追问预演】** 「怎么监控的？」「回滚过吗？」「告警怎么配的？」

## 二、Agent 工作流（占比最大，面试官反复敲打）

### Q6. 工作流是谁派发的任务，还是你自己想做的？是导师提的你来承接吧？
**【答法】** 方向由 〔导师/leader〕 提出，我承接落地 + 方案设计 + 迭代；不是拍脑袋，有 〔提效/业务〕 目标驱动。
**【深入】** 强调「承接」不等于「被动」：我做了可行性评估、拆分子任务、定了验收标准。
**【面试官意图】** 判断项目含金量和你的主动性。
**【追问预演】** 「你自己独立想过别的方案吗？」

### Q7. 全自动串行、第一个任务有问题会放大错误，出现过吗？怎么解决？是逻辑问题还是别的？其他原因？
**【答法】** 出现过；性质是**逻辑问题 + 流程设计缺陷（缺 checkpoint）**；其他根因：上下文窗口限制→注意力分散、提示词歧义、模型误读已有代码（幻觉）、多文件改动一致性失效；解决：关键节点加**人工确认 / 编译+单测门禁**，fail 即停。
**【深入·错误放大链路】**
```
任务1(错误前提) → 任务2(在错误上生成) → 任务3(错误叠加) → CR 时一堆错
```
- 这就是「垃圾进垃圾出」在 Agent 上的放大版。
- 修复手段排序：① 任务拆小、单任务验证；② 自动编译/单测当 gate；③ 人工 checkpoint。
**【面试官意图】** 看你有没有**失败经验**和**根因分析**，而不是只讲成功。
**【追问预演】** 「你怎么知道任务1错了？有自动校验吗？」「错误传导你能定位到哪一步吗？」

### Q8. 同事用后给过什么反馈？生成的代码符合团队规范吗？没考虑加规则约束吗？分析过原因吗？
**【答法】** 反馈：风格不统一、缺注释、不遵循 lint/命名；该加约束：① prompt 注入团队规范；② 生成后 formatter/linter 后处理；③ 用 SpecKit/OpenSpec 规格前置；原因：模型无团队上下文，默认按通用开源风格。
**【深入·可落地的约束手段】**
1. 系统提示固定「编码规范段」（命名/分层/异常处理/日志规范）；
2. 后处理流水线：`gofmt`/`spotless` + `lint` 自动修；
3. 规范做成可检查项，生成后跑 CI 门禁；
4. 用 SpecKit 把「规范 + 验收标准」写进 spec，生成前就约束。
**【面试官意图】** 看你有没有把「个人玩具」做成「团队可用工具」的意识。
**【追问预演】** 「你做过 lint 后处理吗？」→ 诚实说「当时没做，现在认为该做」。

### Q9.（面试官点破最大问题）所有任务串行跑完再让人 CR，AI 代码本就难读，一堆一起生成更难弄。有没有考虑列任务清单、人控制逐个执行、每个 CR 完再执行下一个？
**【答法】** 承认是**最大设计缺陷**；原方案「批量生成→一次性 CR」认知负担爆炸；应改为**任务清单化 + 人工逐任务确认 + 单任务 CR 通过后再下一个**；正呼应 Anthropic 最佳实践「human checkpoint + 渐进式复杂度」（见本库 [[构建最佳实践]]）。
**【深入·改进后流程】**
```
需求 → 生成任务清单(人审) → 取任务1 → AI生成 → 编译/单测gate → 人CR → 通过才执行任务2 → ...
```
- 每步可停、可改、可回滚；CR 粒度从「1000 行」降到「一个任务几十行」。
**【面试官意图】** 这是面试官**手把手教你的改进方向**，接住并表态「这正是我回去要改的」。
**【追问预演】** 「清单谁生成？AI 还是人？」→ 答：AI 起草 + 人确认/增删。

### Q10. 模型生成代码质量不高的原因？任务给多了（改一处 OK，改一百处出错）注意力转移发现过吗？
**【答法】** 质量不高的原因：① 单次任务过多→注意力分散（改 1 处 vs 100 处错误率陡增，亲身观察）；② 缺项目专属上下文；③ 多文件一致性；④ 无验证环节；明确承认「lost in the middle / 注意力转移」确实存在。
**【深入】**
- 「注意力转移」是真实现象：长上下文里模型对中段信息权重低，任务越多越容易漏改/错改。
- 对策：单任务单文件优先、分批、每批带「已完成文件清单」回灌上下文。
**【面试官意图】** 看你有没有**观察到模型行为规律**，而不只是「用过了」。
**【追问预演】** 「你怎么验证质量下降的？有数据吗？」→ 答：可统计「改动文件数 vs 返工次数」的相关性。

### Q13. 你做的东西调研过业界吗？推荐去看 SpecKit 和 OpenSpec。
**【答法】** 当时调研不够现已补：SpecKit/OpenSpec = **规格/需求驱动的代码生成**——先定义 spec（需求+约束+验收），再生成，支持 review/修订闭环，正好解决「生成不符规范、难 CR」。
**【深入·SpecKit/OpenSpec 是什么】**

## 三、Java 与后端八股

### Q15. MySQL 事务的隔离级别？
**【答法】** 4 级；MySQL 默认 **RR**，靠 **MVCC + 间隙锁** 解决幻读。
**【深入】**
- **RU（读未提交）**：能读别人未提交的数据，脏读。几乎不用。
- **RC（读已提交）**：只能读已提交；每次读生成新快照，解决脏读，但**不可重复读**（同一事务两次读结果不同）。Oracle 默认。
- **RR（可重复读，MySQL 默认）**：事务内多次读一致（第一次读建快照，靠 MVCC 版本链 + ReadView）。
  - **MVCC 原理**：每行有隐藏列 `trx_id`/`roll_ptr`，undo log 形成版本链；ReadView 判断哪个版本对当前事务可见。
  - **幻读怎么解决**：普通 SELECT 用快照读（本就不幻读）；当前读（`SELECT ... FOR UPDATE`/`UPDATE`）用 **next-key lock（间隙锁+记录锁）** 锁住区间，防插入。
- **Serializable**：全程加锁，完全串行，性能差。
**【面试官意图】** 八股基础，答出 RR 的 MVCC+间隙锁 才算到位。
**【追问预演】** 「MVCC 怎么实现的？」「快照读和当前读区别？」「间隙锁什么场景死锁？」

### Q16. MySQL 优化做过吗？慢查询这些不了解？
**【答法】** 定位慢日志→EXPLAIN→索引/SQL/架构三层优化；〔补真实案例〕。
**【深入】**
- **定位**：`slow_query_log=1`、`long_query_time`、`EXPLAIN` 看 `type`(最好 ref/range，最差 ALL)、`key`(用没用索引)、`rows`(扫描行)、`Extra`(Using filesort/index)。
- **索引优化**：最左前缀匹配；覆盖索引避免回表；避免 `!=`/`OR`/函数包裹/隐式转换导致索引失效；区分度低的列（如性别）不加。
- **SQL 改写**：`SELECT *`→具体列；深分页 `LIMIT 100000,10`→延迟关联 `JOIN (SELECT id ... LIMIT 100000,10)`。
- **架构**：读写分离、分库分表（按 user_id 哈希）、冷热分离。
- **真实案例模板**：现象(接口 2s)→EXPLAIN(全表扫描)→缺索引/索引失效→加复合索引→降到 20ms。
**【面试官意图】** 面试官明示「感觉你后端没怎么准备」，这里要**拿项目案例砸实**，别只背概念。
**【追问预演】** 「索引为什么失效？」「B+树结构？」「回表是什么？」

### Q17. Java 线程池了解吗？执行流程从添加任务到拒绝？
**【答法】** `ThreadPoolExecutor` 七参数；流程：核心满→入队→队满→开非核心→达 max→拒绝。
**【深入·七参数】**
- `corePoolSize` 核心线程数；`maximumPoolSize` 最大；`keepAliveTime`+`unit` 非核心空闲回收；`workQueue` 阻塞队列；`threadFactory` 线程工厂（命名/埋点）；`handler` 拒绝策略。
**【执行流程细化】**
```
提交任务
 ├─ 当前线程数 < core → 新建核心线程执行
 ├─ 核心满 → 任务入 workQueue
 │   └─ 队列满 → 新建非核心线程（直到 max）
 │       └─ 达 max → handler 拒绝
 └─ 线程执行完从队列取下一个（复用，不销毁）
```
- **拒绝策略**：`AbortPolicy`(抛 RejectedExecutionException，默认)/`DiscardPolicy`(静默丢)/`DiscardOldestPolicy`(丢队首)/`CallerRunsPolicy`(调用者线程自己跑，保消息不丢、反压)。
- **常见坑**：`newFixedThreadPool`/`newCachedThreadPool` 用 `LinkedBlockingQueue` 无界→任务暴增 OOM；要根据业务选有界队列 + 合理拒绝。
**【面试官意图】** 基础必考题，流程要说顺、参数要报全。
**【追问预演】** 「为什么用有界队列？」「CallerRunsPolicy 有什么用？」

### Q18. 线程的创建过程了解吗？
**【答法】** `start()`→JVM 本地方法 `start0`→OS 创建内核线程→调度执行 `run()`；线程池复用 Worker 循环取任务，避免频繁创建。
**【深入】**
- 线程模型：**KLT（内核线程）一对一**，Java 线程直接映射 OS 线程，创建成本高（默认 1MB 栈）。
- 为什么用池：频繁 `new Thread` 开销大、难管控；池化复用、限流、统计。
- 线程状态：NEW→RUNNABLE→(BLOCKED/WAITING/TIMED_WAITING)→TERMINATED。
**【面试官意图】** 考 JVM/OS 底层理解。
**【追问预演】** 「用户态线程和内核线程区别？」「协程了解吗？」

### Q19. MQ 主要使用场景？开发消费者有哪些原则？幂等怎么做？还有吗？
**【答法】** 场景：异步解耦/削峰/最终一致性/广播；消费者原则：幂等+重试+死信+顺序+不阻塞；幂等：唯一ID+去重表/Redis setnx/版本号/状态机；还有：不丢失、不重复、不积压。
**【深入·逐条】**
- **异步解耦**：下单后发消息，库存/积分/通知各自消费，不串行阻塞。
- **削峰**：大促流量进 MQ，下游按能力消费（如 1 万/s 进、2 千/s 出）。
- **幂等实现**：
  - 数据库唯一索引（message_id）+ `INSERT ... ON DUPLICATE`；
  - Redis `SETNX message_id` 成功才处理；
  - 状态机：`status` 从 INIT→PROCESSING→DONE，重复消息命中 DONE 直接跳过。
- **不丢失**：生产端 confirm 机制；消费端**手动 ack**（处理完再 ack，别提前 ack）；
- **顺序消费**：同业务 key（如 order_id）路由到同分区/队列，单线程消费。
**【面试官意图】** 看实战经验，幂等是 MQ 必问。
**【追问预演】** 「消息重复消费会怎样？」「死信队列干嘛的？」「怎么保证顺序？」

### Q20. Redis 怎么保证原子性？用哪个命令实现只消费一条？为什么用 Lua 不用 setnx？
**【答法】** 原子性来自单线程执行命令；只消费一条用 `LPOP/RPOP`（本身原子）；Lua 把多步打包成不可分割执行，避免 `setnx` 后处理之间的竞态，且省 RTT。
**【深入】**
- **单线程**：Redis 命令执行是串行的，单条命令天然原子；但「先 GET 再 SET」两条命令**不原子**，中间可被插空。
- **Lua 脚本**：`EVAL` 执行期间不被其他命令打断，`set key val + expire` 这类「判断+写+过期」整体原子。
- **为什么不用裸 setnx 做分布式锁**：`setnx` 拿到锁后若没设过期时间→宕机死锁；`set nx ex` 一条命令才行；释放锁还要「比对 value 再删」→ 必须用 Lua 保证「比对+删」原子，否则会误删别人锁。
- **只消费一条**：`LPOP` 从 list 左端原子弹出一个，天然「只消费一条」。
**【面试官意图】** 考 Redis 原子性理解和分布式锁正确性。
**【追问预演】** 「Redisson 锁原理？」「锁过期但业务没执行完怎么办？（看门狗）」

### Q21. Spring 事务实现方式有几种？代码怎么写？
**【答法】** 两种：编程式（`TransactionTemplate`）+ 声明式（`@Transactional` AOP）；并主动说坑：自调用失效、只回滚 RuntimeException、捕获异常不回滚、大事务锁表。
**【深入·代码示例】**
```java
// 声明式
@Transactional(rollbackFor = Exception.class,
               isolation = Isolation.REPEATABLE_READ,
               propagation = Propagation.REQUIRED,
               timeout = 3)
public void transfer() { /* 扣款+加款 */ }

// 编程式
transactionTemplate.execute(status -> { /* ... */ return null; });
```
- **传播行为矩阵**（常考）：
  - `REQUIRED`（默认）：有则加入，无则新建；
  - `REQUIRES_NEW`：挂起当前，新建独立（日志/审计常用）；
  - `NESTED`：嵌套保存点，内层回滚不影响外层（依赖 JDBC 保存点）；
  - `SUPPORTS / NOT_SUPPORTED / NEVER / MANDATORY`。
- **自调用失效**：同类 `a()` 调 `@Transactional b()`，因 AOP 基于代理，内部调用绕过代理→不生效；解决：注入自己代理 / 拆类 / 用 `AopContext`。
**【面试官意图】** 面试官直言「感觉你后端没怎么准备」，这题要答出**坑**才翻盘。
**【追问预演】** 「REQUIRES_NEW 和 NESTED 区别？」「大事务怎么拆？」

### Q22. 反转链表指定区间 [left, right]（头插法，O(n)/O(1)）
**【答法】** 虚拟头节点 dummy 统一边界 + 头插法在区间内反转 (right-left) 次。
**【完整代码】**
```java
class ListNode {
    int val;
    ListNode next;
    ListNode(int v) { val = v; }
}

public ListNode reverseBetween(ListNode head, int left, int right) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode pre = dummy;
    // 1. pre 移动到 left 的前一个节点
    for (int i = 1; i < left; i++) pre = pre.next;
    ListNode cur = pre.next;          // 区间第一个节点（头插的"锚"）
    // 2. 头插 (right - left) 次
    for (int i = left; i < right; i++) {
        ListNode nxt = cur.next;      // 要提到前面的节点
        cur.next = nxt.next;          // cur 跳过 nxt
        nxt.next = pre.next;          // nxt 指向当前区间头
        pre.next = nxt;               // pre 接 nxt，nxt 成为新区间头
    }
    return dummy.next;
}
```
**【复杂度】** 时间 O(n)（最多遍历一次），空间 O(1)（仅几个指针）。
**【关键点】**
- `dummy` 消除「head 恰好在区间内被反转」的边界特判；
- 头插法每次把 `cur.next` 提到 `pre` 之后，区间头不断前移；
- 反转次数固定 `right-left`，与区间长度无关，避免多算。
**【边界测试】** `left=1`（head 被反转，靠 dummy 兜住）、`left==right`（不反转）、`right=n`（尾节点）。
**【追问预演】** 「递归怎么写？」「能不能一次遍历同时定位？」「K 个一组反转（LeetCode 25）怎么改？」（= 把区间反转套进循环，每 K 个调一次）。
