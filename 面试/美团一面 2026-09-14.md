## 一、直播间项目与埋点

### Q1. 项目几个人开发、多少 PD、多大体量？只有一个后端吗？
**答（模板，〔待补充真实数字〕）：**
- 团队规模：后端 〔N〕 人，前端 〔N〕 人，PD 〔N〕 人；
- 体量：直播间日均 DAU 〔N〕，峰值 QPS 〔N〕，日均埋点上报量 〔N〕 条；
- 后端是否只有一个：〔是/否〕。若只有一个后端，要强调「负责了埋点采集链路 + 服务端落库 + 查询接口」的端到端模块，体现owner意识。

> 面试要点：面试官在确认你对项目全局的掌控度，别只说自己那块，要能报出体量和协作关系。

### Q2. 埋点上报最终数据存到哪？埋点平台底层怎么存储？会丢吗？
**答：**
- 链路：客户端 SDK → 网关/采集服务 → **消息队列（Kafka）** → 实时计算（Flink）→ 落库；
- 存储分层：
  - 实时 OLAP 查询：**ClickHouse / Doris / Elasticsearch / Druid**（适合聚合分析）；
  - 离线数仓：**Hive / HDFS**（T+1 批量）；
- 会不会丢：
  - Kafka 有 `acks=all` + 生产者重试 + 消费位移手动提交，正常不丢；
  - 风险点在**采集端**：若客户端断网且无本地缓冲，会丢；生产一般做「本地落盘 + 失败重试 + 采样降级」兜底；
  - 一句话：**链路内不丢，极端弱网/客户端崩溃可能丢少量，靠重试+采样兜底**。

### Q3. 上报这个数据合理吗？采集的都是什么数据？为什么这种数据要存到服务端？
**答：**
- 合理性：行为埋点是行业标准做法，用来衡量「曝光→点击→停留→转化」漏斗，指导推荐和运营，合理；
- 采集数据：进入/离开直播间、商品点击、下单、停留时长、滑屏、设备/网络/地域等上下文；
- 为什么存服务端：
  1. **客户端不可信**：本地数据可被篡改、易丢失；
  2. **统一清洗**：去重、补全用户画像、关联维度；
  3. **支撑 BI/推荐**：服务端是数据分析的单一事实源。

### Q4. 有没有开发时才发现不该由你们来开发的例子？没有技术方案吗？
**答（诚实复盘）：**

### Q5. 上线之后有没有问题？线上 bug 之类？
**答（〔填真实案例〕）：**
- 例：某次大促埋点量翻倍，Kafka 消费堆积、ClickHouse 写入延迟，下游看板数据延迟；

## 二、Agent 工作流（占比最大，面试官反复敲打）

### Q6. 工作流是谁派发的任务，还是你自己想做的？是导师提的你来承接吧？
**答（诚实）：** 方向由 〔导师/leader〕 提出，我负责**承接落地 + 方案设计 + 迭代**。强调不是“拍脑袋”，而是有业务/提效目标驱动。

### Q7. 任务先执行再检查再继续、全自动，第一个任务代码有问题会放大错误，出现过吗？怎么解决？是逻辑问题还是别的？还有其他原因吗？
**答：**
- **出现过**：串行全自动 + 无中间校验，错误前提 → 错误代码 → 后续任务在错误基础上继续，错误被放大；
- 性质：**既有逻辑问题，也有流程设计问题**（缺少 checkpoint）；
- 其他原因：① 上下文窗口限制导致模型「注意力分散 / lost in the middle」；② 提示词歧义；③ 模型误读已有代码（幻觉）；④ 多文件改动时一致性失效；
- 解决方向：在关键节点加**人工确认 / 自动编译+单测门禁**，fail 即停。

### Q8. 同事用后给过什么反馈？生成的代码符合团队规范吗？没考虑加规则约束吗？分析过原因吗？
**答：**
- 反馈：风格不统一、缺注释、不遵循团队 lint/命名规范；
- 该加约束：① prompt 注入团队规范/编码标准；② 生成后用 **formatter/linter 后处理**；③ 用 **SpecKit / OpenSpec** 这类规格驱动框架，把规范前置；
- 原因分析：模型没有团队上下文，默认按「通用开源风格」生成，需在流程里显式喂规范。

### Q9.（面试官点破最大问题）所有任务串行跑完再让人 CR，AI 代码本就难读，一堆一起生成更难弄。有没有考虑列任务清单、人控制逐个执行、每个 CR 完再执行下一个？
**答（承认这是最大设计缺陷）：**
- 原方案缺陷：批量生成 → 人类一次性 CR 一堆陌生代码 → 认知负担爆炸、易漏；
- 应改为：**任务清单化 + 人工逐任务确认 + 单任务 CR 通过后再执行下一个**；
- 这正呼应 Anthropic 的最佳实践「**human checkpoint（人工检查点）+ 渐进式复杂度**」——见本库 [[构建最佳实践]]。

### Q10. 用 AI 这么久，模型生成代码质量不高的原因？任务给多了（改一处日志 OK，改一百处就出错）注意力转移发现过吗？
**答：**
- 质量不高的原因：
  1. **单次任务过多 → 注意力分散**（改 1 处 vs 改 100 处，错误率陡增，这正是你亲身观察到的）；
  2. 缺项目专属上下文（架构/规范/历史决策）；
  3. 复杂多文件改动的一致性问题；
  4. 没有验证环节（编译/单测门禁）；
- 明确承认：**「注意力转移 / lost in the middle」现象确实存在**，所以要把大任务拆小、分步执行验证。

## 三、Java 与后端八股

### Q15. MySQL 事务的隔离级别？
**答：** 4 级，并发问题递进解决：
| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| 读未提交 RU | ❌ | ❌ | ❌ |
| 读已提交 RC | ✅ | ❌ | ❌ |
| 可重复读 RR（MySQL 默认） | ✅ | ✅ | ✅(靠 MVCC+间隙锁) |
| 串行化 Serializable | ✅ | ✅ | ✅ |

- MySQL 在 **RR** 下通过 **MVCC + 间隙锁（next-key lock）** 解决幻读。

### Q16. MySQL 优化做过吗？慢查询这些不了解？
**答：**
- 定位：`slow_query_log` 开慢日志 → `EXPLAIN` 看执行计划（type、key、rows、Extra）；
- 索引优化：最左前缀、覆盖索引、避免隐式转换/函数包裹导致索引失效、区分度低的列不加；
- SQL 改写：少用 `SELECT *`、深分页用游标/延迟关联；
- 架构：读写分离、分库分表、冷热分离；
- 〔补一个自己项目的真实慢查询案例：现象→EXPLAIN→加索引/改写→提升倍数〕。

### Q17. Java 线程池了解吗？执行流程从添加任务到拒绝？
**答：** `ThreadPoolExecutor` 七大参数：`corePoolSize / maxPoolSize / keepAliveTime / unit / workQueue / threadFactory / handler`。
- 提交流程：**核心线程未满 → 建核心线程**；**核心满 → 入队列**；**队列满 → 建非核心线程**；**达 maxPoolSize → 触发拒绝策略**；
- 拒绝策略：`AbortPolicy`（抛异常）/ `DiscardPolicy`（静默丢弃）/ `DiscardOldestPolicy`（丢最旧）/ `CallerRunsPolicy`（调用者线程执行）。

### Q18. 线程的创建过程了解吗？
**答：**
- `new Thread().start()` → JVM 调本地方法 `start0` → 操作系统创建**内核线程（KLT）** → 调度器分配时间片执行 `run()`；
- 线程池场景复用：Worker 循环从阻塞队列取任务执行，避免频繁创建/销毁内核线程的开销。

### Q19. MQ 主要使用场景？开发消费者原则？幂等怎么做？还有吗？
**答：**
- 场景：**异步解耦、流量削峰、最终一致性、广播**；
- 消费者原则：① **幂等**（核心）；② 消费失败重试 + 死信队列；③ 顺序消费（同 shard key）；④ 不在消费逻辑里做长耗时阻塞；
- 幂等做法：**唯一消息 ID + 去重表 / Redis setnx / 版本号 / 状态机**；
- 还有：消息**不丢失**（生产 confirm + 消费手动 ack）、**不重复**（幂等）、**不积压**（监控 lag）。

### Q20. Redis 怎么保证原子性？用哪个命令实现只消费一条？为什么用 Lua 不用 setnx？
**答：**
- 原子性来源：Redis **单线程执行命令**，单条命令天然原子；
- 只消费一条：**`LPOP` / `RPOP`**（本身就是原子出队）；
- 为什么用 **Lua 脚本**而不是裸 `setnx`：Lua 把「判断+扣减」多步操作打包成**一段不可分割的执行**，执行期间不被其他命令打断，避免 `setnx` 成功后、`get`/处理 之间的竞态；且减少网络 RTT。

### Q21. Spring 事务实现方式有几种？代码怎么写？
**答：** 两种：**编程式**（`TransactionTemplate`）和**声明式**（`@Transactional`，基于 AOP）。
- 声明式示例：
  ```java
  @Transactional(rollbackFor = Exception.class,
                 isolation = Isolation.REPEATABLE_READ,
                 propagation = Propagation.REQUIRED)
  public void transfer() { /* ... */ }
  ```
- 常见坑（面试官觉得没准备，要主动说）：① **自调用失效**（同类方法调 `@Transactional` 方法，AOP 不生效）；② 默认只回滚 `RuntimeException`；③ 事务方法内捕获异常导致不回滚；④ 长事务/大事务锁表。

## 四、手撕

### Q22. 反转链表指定区间 [left, right]（头插法，O(n)/O(1)）
**答（Java，虚拟头节点 + 头插法）：**
```java
class ListNode {
    int val;
    ListNode next;
    ListNode(int v) { val = v; }
}

public ListNode reverseBetween(ListNode head, int left, int right) {
    ListNode dummy = new ListNode(0);   // 虚拟头，统一边界
    dummy.next = head;
    ListNode pre = dummy;
    for (int i = 1; i < left; i++) pre = pre.next; // 移动到 left 前一个
    ListNode cur = pre.next;                         // 区间第一个节点
    // 在区间内做 (right-left) 次头插
    for (int i = left; i < right; i++) {
        ListNode nxt = cur.next;     // 待提到前面的节点
        cur.next = nxt.next;         // 跳过 nxt
        nxt.next = pre.next;         // nxt 指向当前区间头
        pre.next = nxt;              // pre 接上 nxt，nxt 成为新区间头
    }
    return dummy.next;
}
```
- 复杂度：时间 O(n)（只遍历一次），空间 O(1)（仅几个指针）；
- 关键点：**dummy 节点**消除 head 可能被反转的边界特判；头插法每次把 `cur.next` 提到 `pre` 之后。
